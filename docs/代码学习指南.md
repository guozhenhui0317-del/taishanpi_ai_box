# 泰山派 AI Box 代码学习指南

本文面向希望读懂和修改项目的学习者，基于仓库当前代码编写。建议打开编辑器，一边看本文，一边跟随链接阅读源码。文中的“本地 AI 助手”指主界面的 **AI助手**；“小智联网”指另一个独立入口。

## 1. 项目做什么

程序运行在 RK3566 泰山派的 Debian 图形桌面上，使用官方 3.1 寸 MIPI 屏、触摸屏、麦克风和扬声器。主界面依次有五个入口：AI助手、天气、小智联网、网络设置、旋转屏幕。

- 本地 AI：Vosk 在板上识别语音，Ollama 在板上运行大模型，Piper 将回答合成为中文语音。模型使用 SD 卡。
- 小智联网：板上采集和播放音频，通过小智协议与官方服务交换音频和文字；不读取本地 AI 模型。
- 天气：通过 Open-Meteo 获取成都天气。
- 网络设置：通过 NetworkManager 的 `nmcli` 扫描、连接 Wi-Fi。
- 旋转屏幕：只旋转 AI Box 绘制的画面，并同步转换触摸坐标。

**语音识别 ASR**是声音转文字；**大模型 LLM**负责根据输入生成回答；**语音合成 TTS**是文字转声音。小智联网时，声音会发给所选官方服务；本地对话处理发生在开发板，但网络天气仍需联网。项目当前不使用 AHT30 和 ST7789。

```text

│   ├── __main__.py            命令行入口

│   ├── xiaozhi.py             小智激活、Opus 音频与 WebSocket
│   ├── weather.py             成都天气请求、缓存与文字格式化
│   ├── wifi.py                Wi-Fi 扫描、连接与触摸界面
│   └── hardware/gpio.py       Linux GPIO 编号与访问工具
├── deployment/
│   ├── ai-box-mipi            图形会话启动包装脚本
│   ├── ai-box-ollama          Ollama 启动及 SD 卡检查脚本
│   └── ai-box-speak           调用 Piper 并将音频交给 aplay
```

`__init__.py` 表示 Python 包。`tests/` 中的代码用于验证行为，不承担产品界面功能。仓库不包含操作系统镜像、Ollama/Piper 可执行程序、兼容运行库和模型文件；这些需要在目标板另行准备，单独克隆仓库不能直接还原整机环境。

## 3. 从入口到界面：先读这一条

```text
python3 -m ai_box mipi
  -> ai_box/__main__.py: main()
  -> ai_box/mipi.py: main()
  -> TouchDisplay + Screen + WifiPanel + Application
  -> Tk 主线程接收触摸、显示图像
  -> Application 工作线程管理菜单与后台任务
```

### 3.1 命令入口：`ai_box/__main__.py`

- `main(argv=None)`：使用 `argparse` 解析 `run`、`mipi` 和 `voice`。前两者打开主界面；`voice` 打开界面后直接进入本地 AI 助手。
- 当模块以 `python3 -m ai_box` 执行时，底部的 `if __name__ == "__main__"` 调用 `main()`。
- 图形依赖在参数解析后才导入，因此查看 `--help` 不必先初始化屏幕。

### 3.2 窗口和触摸：`ai_box/mipi.py`

`TouchDisplay` 把 Tk 窗口与程序内部绘制的图片连接起来：

| 函数 | 输入与作用 |
| --- | --- |
| `__init__(root)` | 读取物理屏幕宽高、恢复方向，创建全屏 Tk 标签和容量为 1 的图片队列。 |
| `_set_size()` | 根据 0°/90°/180°/270° 计算逻辑画面宽高；90° 和 270° 时交换宽高。 |
| `rotate()` | 将方向加 90°、写入 `/var/lib/ai-box/orientation`，并丢弃旧尺寸的待显示图像。 |
| `touch_point(event)` | 根据当前方向，把 Tk 物理触摸坐标映射到逻辑画面坐标。 |
| `touch_x(event)` | 返回 `touch_point()` 的横坐标，是较简短的坐标接口。 |
| `display(frame)` | 把最新 Pillow 图片放进队列；队列满时丢弃旧帧，避免界面越来越迟。 |
| `refresh()` | 由 Tk 主线程取出最新帧，按方向旋转并显示。 |

`main(voice_only=False)` 创建上述对象，启动 `Application.run()` 工作线程，并把 Tk 触摸事件路由到 Wi-Fi 页面或主菜单。Tk 绘图仍由主线程执行；其他线程只提交图片。退出时通过 `ExitStack` 停止应用线程并销毁窗口。

**阅读重点：**图片旋转和坐标转换必须成对修改。如果只旋转画面，点击的将是错误位置；`tests/test_launcher.py` 用四个角度验证了映射。

### 3.3 应用调度：`ai_box/app.py`

`Application` 是菜单和功能之间的协调者。它不直接实现音频编码或 Wi-Fi 协议，而是把工作交给专门模块。

| 函数 | 作用 |
| --- | --- |
| `__init__(screen, buttons, rotate, network)` | 保存界面与可选硬件接口，生成菜单，创建锁、停止事件、天气缓存和线程状态。 |
| `move(delta)` | 硬件按键方式下移动选择项；正在语音对话时不切换菜单。 |
| `select(index=None, touch=False)` | 打开选中图标；若天气或语音页面正在运行，则返回或请求停止。 |
| `_open_selected()` | 根据菜单名称启动本地/小智语音、打开天气或网络页、调用旋转函数。语音在工作线程执行。 |
| `handle_voice_command(text)` | 本地模式中识别天气关键词，直接查成都天气并播报；未匹配返回 `False`，交给大模型。 |
| `_start_forecast()` / `_update_forecast()` | 启动后台天气查询并写回结果，限制重复请求，避免网络请求阻塞触摸。 |
| `_run_voice(mode)` | 按入口选择 `VoiceAssistant` 或 `XiaozhiAssistant`；结束时释放资源、显示错误或回到菜单。 |
| `_poll_buttons()` | 为可选 GPIO 按钮检测按下边沿和简单消抖；官方触摸屏主要使用 Tk 触摸。 |
| `render()` | 根据当前状态绘制主菜单或天气页；语音与网络页面占用屏幕时不覆盖。 |
| `refresh_menu()` | Wi-Fi 页面退出后标记主界面需要重绘。 |
| `run()` / `close()` | 启动按钮线程、循环渲染；退出时设置停止事件并等待工作线程结束。 |

`threading.Lock` 防止多个线程同时改菜单状态；`threading.Event` 用于通知语音任务停止。函数名前的 `_` 表示项目约定的内部实现，不是 Python 的强制访问限制。

### 3.4 图像绘制：`ai_box/ui.py`

`Screen` 提供上层需要的绘图操作，底层函数返回 Pillow `Image`：

- `Screen.__init__()` 保存显示对象和字体，并准备较小的思考文字字体。
- `set_voice_mode(enabled)` 控制语音页面返回栏；`_with_back(image)` 给页面加返回区域。
- `text(text)` 显示普通文字；`weather(text)` 显示天气；`response(question, stage, content)` 显示问题、状态和逐步增长的回复；`menu(items, index)` 绘制应用图标；`face(state)` 绘制等待说话的人脸。
- `load_font()` 加载中文字体，可通过 `AI_BOX_FONT`、`AI_BOX_FONT_SIZE` 指定。
- `text_frame(...)` 将文字按画面宽度换行，思考内容可用倾斜效果。
- `menu_boxes(width, height, count)` 计算每个图标的矩形；`menu_index_at(...)` 用**同一套矩形**将点击坐标转换为索引。
- `menu_frame(...)` 根据图标名称绘制颜色、图形和文字；`face_frame(...)` 绘制三种嘴部状态。

图标显示顺序由 `Application.main_menu` 决定，具体画法在 `menu_frame()`；新增图标通常要同时处理菜单、触摸后的分支和绘图样式。

## 4. 本地 AI 助手：从声音到声音

```text
麦克风 -> PyAudio -> Vosk -> 识别文字
    -> 天气关键词？是：直接查询天气
    -> 否：Ollama 本地大模型 -> 流式文字 -> 屏幕
                                  -> 分段队列 -> Piper -> aplay -> 扬声器
```

实现集中在 [`ai_box/voice.py`](../ai_box/voice.py)。

### 4.1 模型与文本辅助函数

| 函数 | 作用 |
| --- | --- |
| `log(message)` | 以时间戳输出日志并立即刷新。 |
| `check_models(model_name=None)` | 要求 `/mnt/modelsd` 为挂载点，检查指定 Ollama 模型 manifest 中每个 blob 的名称及文件大小，并检查 Vosk 模型的 `am/final.mdl`。它检查文件大小，**不会重新计算 blob 的 SHA-256 内容校验值**。 |
| `split_reasoning(text)` | 将 DeepSeek 输出中的 `<think>…</think>` 与正式回答拆开，处理流式输出中尚未完整到达的结束标签。 |
| `split_speech(text, final=False)` | 按句号、问号、分号、换行等切分已生成文本；较长分句可在逗号处分割，过长时强制切段，返回“可播报段”和“未完成部分”。 |

例如，输入还只有 `你好，今天天` 时，最后一段可能继续等待；后续出现句号或达到长度条件后，才加入播报队列。`final=True` 用于模型结束时清空尾段。

### 4.2 `VoiceAssistant` 的方法

- `__init__(screen)`：选模型、检查 SD 卡、延迟导入 Vosk/PyAudio/Ollama，加载识别器并创建 Ollama 客户端与音频对象。默认模型由 `AI_BOX_LLM_MODEL` 选择，代码默认 `qwen2:0.5b`，板上实际值取决于配置。
- `_stopped()`：综合检查资源关闭、用户退出和播报失败事件。
- `_listen()`：以 16 kHz 采集；优先打开双声道并取左声道，失败时尝试单声道。回调把音频块放入有界队列，主循环取出交给 Vosk；如果队列或音频溢出，则明确报错，避免悄悄丢失音频。
- `speak(text)`：移除部分格式符，调用 `/opt/ai-box/deployment/ai-box-speak`，等待播报结束；退出时终止进程组。源码支持 `AI_BOX_SPEECH=0` 跳过本地播报，需部署包含该功能的版本后才生效。
- `_request_reply(messages)`：普通模型用 Ollama `chat`；DeepSeek 使用 `generate`，显式拼接提示词，设置线程数、上下文和输出长度，并流式读取。
- `reply(text, stop_event)`：读取流式文本，更新屏幕；DeepSeek 的思考与正式回答分开。函数内部的 `enqueue()` 将可播报段加入容量为 8 的队列，`play_segments()` 在独立线程按顺序调用 `speak()`。结束时关闭流并等待播报线程；仅将正式回答写入最近两轮历史。
- `run(stop_event, handle_command)`：循环听音；先让应用处理天气等本地命令，其余文本交给 `reply()`。
- `close()`：通过 `ExitStack` 释放 Ollama 客户端和 PyAudio 资源，可重复调用。

注意：**思考内容只显示，不播报**。因此 DeepSeek 很久都在思考时，即使分段播报正常，也要等正式回答出现才开始说话。当前 Piper 是每段启动一次，段间会有加载延迟。

### 4.3 `deployment/ai-box-speak`

这个 Bash 脚本检查 SD 卡及 `piper-voices/zh_CN-huayan-medium.onnx` 和配置文件，然后使用 `/opt/ai-box/tts-runtime/` 中的隔离动态加载器启动 Piper，生成 22050 Hz 单声道 PCM，并通过管道交给 `aplay`。`set -o pipefail` 让管道中间的失败也能反映到退出状态。

这里使用隔离运行库是为适配当前较旧的 Debian 用户空间；不要把这些库添加到全系统 `LD_LIBRARY_PATH`。模型在 SD 卡，运行程序及兼容库在 eMMC。

## 5. 小智联网：激活、协议与音频

```text
点击小智联网
  -> 读取设备身份 -> 官方 OTA 接口 -> 需要时显示绑定码
  -> WSS WebSocket 握手
  -> 麦克风 PCM -> Opus 编码 -> 网络服务
  -> 服务返回识别文字、回复文字和 Opus 音频
  -> 屏幕显示 + Opus 解码 + 扬声器播放
```

实现位于 [`ai_box/xiaozhi.py`](../ai_box/xiaozhi.py)。这里的 OTA 请求用于获取服务配置和激活信息；本程序**不会通过这个接口刷写固件**。

### 5.1 连接和激活函数

- `identity()`：从 `/sys/class/net/wlan0/address` 读取设备 MAC，在 `/var/lib/ai-box/xiaozhi-client-id` 读取或生成并保存客户端 UUID。身份用于官方设备绑定，文件需要相应读写权限。
- `post_ota(path, headers, payload)`：向官方 OTA 地址发送 JSON POST，返回 HTTP 状态和响应数据；使用超时，避免无限等待。
- `connection_config(screen, stop)`：请求配置。服务要求绑定时，在屏幕显示激活码，轮询 `activate`；等待超时按待绑定处理，直到绑定成功或用户退出。然后重新获取 WebSocket 配置。

### 5.2 `Opus` 类

Opus 是音频压缩格式。项目用 `ctypes` 调用系统 `libopus`，所以 Python 包之外还需要系统库：

- `__init__(output_rate)`：创建 16 kHz 单声道编码器和按服务端采样率配置的解码器。
- `encode(pcm)`：将 60 ms、16 kHz、16 位单声道 PCM 编码为一个 Opus 包。
- `decode(packet)`：将服务端一个 Opus 包解码成单声道 PCM。
- `close()`：释放本地库中的编码器和解码器对象。

`ctypes` 直接操作 C 库，参数类型、缓冲区大小和资源释放都需要特别小心；`tests/test_xiaozhi.py` 有编解码往返检查。

### 5.3 `XiaozhiAssistant`

- `__init__(screen)` 保存界面，不加载 Vosk、Ollama 或 SD 卡模型。
- `run(stop, handle_command=None)` 先激活并建立 **WSS** 连接，发送 `hello`，读取服务端音频参数；再打开 PyAudio 输入输出。麦克风回调写入有界队列，主循环编码并发送 Opus 包；收到 `stt` 显示识别文字，收到 `tts` 状态和音频包时显示回复并解码播放。
- 播放期间暂停发送麦克风数据，播放结束后再次进入收听；这是当前实现的半双工流程。点击屏幕会设置停止事件并释放资源。
- `close()` 是与应用调度器一致的生命周期接口；实际会话资源在 `run()` 的 `finally` 中释放。

当前小智入口没有实现语音唤醒、回声消除或设备 MCP 控制。它与本地 `handle_voice_command()` 的天气快捷处理是两条独立路径；小智如何回答天气取决于其服务配置。

## 6. 天气和网络设置

### 6.1 `ai_box/weather.py`

- `URL` 规定成都经纬度、当前数据、未来两天字段及上海时区；`CONDITIONS` 将天气代码转换为中文。
- `Forecast.__init__()` 创建互斥锁与缓存；`get()` 请求 JSON，验证所需字段和日期，成功缓存 600 秒。普通网络失败会重试一次并短暂缓存失败；HTTP 错误使用不同的失败缓存时间。
- `forecast_text(data, tomorrow=False)` 把当前、今日或明日数据转成屏幕和语音使用的文字；数据不可用时返回提示。

天气页由 `Application` 后台线程调用，防止慢网络阻塞主界面。当前城市写在 `URL` 中，修改城市时必须同时更新经纬度和显示文字。

### 6.2 `ai_box/wifi.py`

| 函数 | 作用 |
| --- | --- |
| `_fields(line)` | 解析 `nmcli` 的转义冒号和反斜杠，避免把 SSID 中的分隔符误拆开。 |
| `_nmcli(*args, input_text=None, timeout=12)` | 通过参数列表启动 `nmcli`，可通过标准输入传入密码，限制等待时间。 |
| `scan_networks()` | 扫描 `wlan0`，合并同名网络、查询已保存配置 UUID，并按连接状态和信号排序。 |
| `connect_network(network, password=None)` | 连接已保存、开放或密码网络；失败后尝试恢复原连接。 |
| `WifiPanel.__init__()` / `open()` | 创建页面状态、键盘和锁；打开后发起扫描。 |
| `_scan_locked()` / `_scan(generation)` | 在后台扫描；使用 generation 防止旧扫描结果覆盖新页面。 |
| `_start_connect_locked()` / `_connect()` | 在后台连接，完成后更新列表或错误提示。 |
| `touch(x, y)` | 根据列表、键盘或连接状态处理触摸；检查密码长度和网络安全类型。 |
| `_draw_locked()` | 绘制列表或软键盘，密码以星号显示。 |

切换 Wi-Fi 可能改变开发板 IP；NetworkManager 管理已保存的连接。当前 UI 不支持所有企业网络或加密类型。

## 7. GPIO 与启动脚本

[`ai_box/hardware/gpio.py`](../ai_box/hardware/gpio.py) 是通用 GPIO 辅助代码，不是当前 MIPI 触摸屏的必经路径：

- `gpio_number(bank, offset)` 根据 `/sys/class/gpio` 下 gpiochip 的标签、基址和引脚数查找 Linux GPIO 编号。
- `GPIO.__init__()` 按需 export 并配置输入/输出；`value` 属性读取电平，设置属性可改变输出电平；`close()` 释放本对象导出的 GPIO。

`deployment/ai-box-mipi` 从 `/etc/default/ai-box` 读取可选配置，设置字体、无缓冲日志等环境变量，再调用 `/usr/local/bin/ai-box mipi`。非交互启动时，输出写入 `/run/ai-box/ai-box.log`。

`deployment/ai-box-ollama` 检查 SD 卡、选择的模型 manifest 和对应 blob，设置 `OLLAMA_MODELS` 后启动板上的 Ollama 服务。脚本中的具体模型 blob 名称对应当前已适配模型版本；更换模型时要检查脚本和 manifest 是否一致。

这些脚本是部署文件，仓库不会自动创建 systemd 服务、安装模型或配置开机启动。实际板子的 `/usr/local/bin/ai-box`、系统服务和 `/etc/default/ai-box` 属于运行环境，需要单独维护。

## 8. 线程与资源释放

| 执行位置 | 主要工作 | 如何协调 |
| --- | --- | --- |
| Tk 主线程 | 接收点击、取最新图片显示 | `TouchDisplay.frames` 容量为 1；`refresh()` 定时执行。 |
| 应用线程 | 菜单状态、触发重绘 | `Application._lock` 保护共享状态。 |
| 天气/Wi-Fi 线程 | 网络请求、扫描和连接 | 操作结束后更新状态；Wi-Fi generation 排除过期扫描。 |
| 语音工作线程 | 本地或小智一次会话 | `_voice_stop` 通知退出；`ExitStack` 和 `finally` 释放资源。 |
| 本地播报线程 | 消费已完成的回答分段 | 有界 `speech_queue` 保持顺序并限制积压。 |
| PortAudio 回调 | 把采集音频放入队列 | 业务线程处理识别或编码，溢出时显式报错。 |

调试线程问题时，先确认是谁拥有屏幕、谁持有锁、退出事件是否设置，以及是否有阻塞中的网络或音频调用。

## 10. 从问题反查代码

| 现象 | 优先检查 |
| --- | --- |
| 点击图标打开错误页面 | `mipi.py: touch_point()`、`ui.py: menu_boxes()` / `menu_index_at()`、`app.py: _open_selected()`。 |
| 本地助手提示 SD 卡或模型缺失 | 挂载点和模型目录、`voice.py: check_models()`、`deployment/ai-box-ollama`。 |
| 说话被识别错或提示音频溢出 | `voice.py: _listen()` 中声道、音频队列与 Vosk；先检查麦克风和实际识别日志。 |
| 本地模型在输出思考但不播报 | `split_reasoning()` 和 `reply()`：思考不播报，正式回答切段后才送 TTS。 |
| 中文有文字但本地没声音 | `speak()`、`deployment/ai-box-speak`、SD 卡上的 Piper 模型、音频设备；查看进程退出状态。 |
| 小智要求重新绑定 | 网络、`identity()` 保存的客户端 UUID、`connection_config()` 的 OTA/激活响应。 |
| 小智无识别或无声音 | `XiaozhiAssistant.run()` 的输入队列、WSS、服务端 `stt`/`tts` 消息及 Opus 解码播放。 |
| 成都天气不可用 | 先检查网络，再看 `Forecast.get()` 的请求、错误日志、日期和缓存。 |
| Wi-Fi 扫描或连接失败 | `nmcli` / NetworkManager 状态、`scan_networks()`、`connect_network()`。 |

## 11. 测试和建议的学习顺序

在具备 Python 依赖、Pillow、中文或 DejaVu 测试字体及系统 libopus 的环境中：

```sh
python3 -m unittest discover -s tests -v
```

也可单独运行某一组：

```sh
python3 -m unittest discover -s tests -p 'test_xiaozhi.py' -v
python3 -m unittest discover -s tests -p 'test_launcher.py' -v
```

测试会模拟设备或网络，不能代替屏幕、Wi-Fi、麦克风和扬声器实机测试。老系统安装依赖时需确认 Python、二进制库与 glibc 架构兼容；不要直接升级板子的系统 glibc。

推荐按这个顺序练习：

1. 阅读 `__main__.py`、`mipi.py`、`app.py`，画出从点击图标到打开页面的调用链。
2. 修改 `ui.py` 中某个图标的颜色，运行界面相关测试，再到板上观察。
3. 阅读 `weather.py` 和测试，解释为什么网络请求不阻塞触摸。
4. 跟踪 `voice.py` 的 `_listen()` → `reply()` → `speak()`，理解队列与停止事件。
5. 对照 `xiaozhi.py` 中的 `hello`、`listen`、`stt`、`tts` 消息，理解网络语音协议。
6. 再阅读 `wifi.py` 的后台扫描、密码输入和失败恢复逻辑。
